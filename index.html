THE PIVOT

Keep the privacy.
Connect the intelligence.

Manifest does not become another centralized chat service. The local app remains the user's personal AI node. The new layer is a voluntary network that coordinates useful work across many independently owned computers.

01
Personal AI Node

Conversations, files, memory, and local inference remain on the user's own computer by default.

02
Contribution Layer

The user can separately allow performance data, idle compute, approved learning packets, or occasional human feedback.

03
Manifest Commons

Approved contributions are normalized into a shared, model-independent intelligence layer with provenance and licensing controls.

04
Community Intelligence

The network evaluates open models, creates training data, tests community model candidates, and learns what actually works on real hardware.

05
Shared Value

Useful participation can earn credits and, eventually, support a legal structure for broader community participation in network value.

PARTICIPATION

Contribute what you choose.
Keep the rest private.

Someone can contribute compute without sharing chats. Another person can share anonymous performance results but no compute. A third can remain entirely private. Manifest should still be useful in every case.

COMMUNITY-TRAINED MODELS

Different models in.
Shared intelligence out.

Members do not need to run the same open-source model. Manifest can learn from outcomes across the ecosystem and convert useful results into a common training and evaluation format.

01Heterogeneous local models

Qwen, Llama, Mistral, community fine-tunes, and future compatible open-weight models.

→
02Normalized learning

Tasks, outcomes, corrections, rankings, benchmarks, and verified successes enter a common format.

→
03Distributed evaluation

Thousands of devices can independently test candidate models and generate or verify data.

→
04Focused training

Manifest can rent concentrated GPU capacity when a real training run benefits from tightly coupled hardware.

→
05Manifest Community Models

Improved models go back to members and are evaluated again across the network.

The goal is not to buy a giant data center.Use community hardware for the work that distributes well. Rent centralized compute only for the work that actually needs it.
CONTRIBUTION ECONOMY

Turn unused computing power into intelligence you can spend.

Manifest should not ask users to donate value to a company for nothing. The network can make contribution reciprocal.

GIVE

Contribute spare resources.

Idle compute, useful evaluations, approved learning, or human feedback generate contribution receipts.

EARN

Build network credits.

Verified contribution accumulates as service credits rather than a speculative token.

USE

Call on more intelligence.

Spend credits on network compute, larger models, remote agents, storage, or services beyond what one device can handle.

SHARE

Participate in long-term value.

Subject to legal and governance design, the people who help create the network should have a path to participate in the value it creates.

TRUST ARCHITECTURE

The network only works if people can trust the boundary.

Raw chats off by default.

Removing a username does not make conversation content anonymous.

Compute ≠ data permission.

A user can lend GPU time while keeping every personal conversation private.

Inspect what leaves.

Contribution history and permissions should be visible at the device level.

Useful even at zero contribution.

Private-only users remain first-class users rather than being punished for opting out.

License-aware training.

Model outputs and datasets enter training only when their licenses permit it.

No speculative token dependency.

Credits begin as service accounting. Any ownership or revenue-sharing structure comes later and must be legally designed.
